# 45. Changer de modèle sans casser son workflow

**Statut :** idée, non rédigée. **Effort :** moyen. **Thème :** LLM.

**Thèse.** Un modèle change ou disparaît. Un workflow robuste survit à ce changement parce qu'on l'a testé.

## Plan

1. Pourquoi on change : nouvelle version, dépréciation, coût.
2. Épingler la version utilisée (voir 53) pour que le changement soit un choix.
3. Un jeu de cas représentatifs, évalué avant et après (voir 20).
4. Lire les écarts : ce qui s'améliore, ce qui régresse, ce qui varie.
5. Le plan de retour arrière.

## Matière

- **À vous :** une vraie migration, avec les écarts constatés.
- **À recouper :** la politique de dépréciation des modèles de votre fournisseur, dans sa documentation.

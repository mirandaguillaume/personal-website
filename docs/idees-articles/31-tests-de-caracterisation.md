# 31. Tests de caractérisation : tester du legacy sans le toucher

**Statut :** idée, non rédigée. **Effort :** moyen.

**Thèse.** Avant de refactorer du code sans tests, figer son comportement actuel.

## Plan

1. Le code qu'on n'ose pas toucher (à vous : un cas vécu).
2. Des tests qui décrivent ce que le code fait, pas ce qu'il devrait faire.
3. Les tests d'approbation ou de snapshot : outils disponibles côté PHP (à recouper).
4. Juger la qualité du filet avec le mutation testing, comme dans l'article existant.
5. Quand jeter ces tests.

## Matière

- **À vous :** le cas de départ.
- **À recouper :** la définition de « characterization test » dans sa source d'origine, avant de la citer.
